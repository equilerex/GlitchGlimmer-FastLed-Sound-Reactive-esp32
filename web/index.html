What you are looking at

Neither view is a JavaScript rewrite of the animations. The recording is the output of the host harness in src/sim_main.cpp, which compiles the same LEDStripController, SceneDirector and layer code the firmware ships and drives it with a scripted audio timeline.

The live view is that same code compiled to WebAssembly by tools/build-wasm.sh and stepped once per frame from the page. Your microphone's samples go into AudioProcessor unchanged, so the FFT, the feature extraction, the beat detector and the mood classifier are the firmware's own, and the pixels are what the device would have written for that sound.

The microphone needs a secure context: https, or localhost. Opened over file:// the browser exposes no microphone API at all, and the view falls back to a synthetic signal.
